## Limitations that remain

1. The pre-fix active-failover trial saw 100% baseline loss and the first baseline-only test saw 50.0% loss because the controller wrote telemetry to the wrong path. After correcting the telemetry destination, the baseline-only test passed with 0.0% loss. The pre-fix trial remains invalid; each failover trial must establish a fresh healthy baseline before injecting a fault.
2. The pre-fix attempt did not inject a fault; the five post-fix trials did. All five failed to validate failover because the alternate endpoint stayed BLOCK. Validated recovery min/median/max are N/A. The 90-second window did not make this test pass, but the results do not isolate observation-window length as the cause of the earlier failure.
3. The historical failover tests used Linux interface-down or OpenFlow administrative-down, not a confirmed physical cable unplug.
4. Ryu required a temporary compatibility shim outside the repository because of an Ryu/eventlet import incompatibility. The shim does not modify project safety logic, but it is a test-environment caveat.
5. Qwen 2.5 Coder 1.5B produced 30 fenced JSON responses, which the frozen strict parser rejected. Fallback was 100%; this evaluation did not exercise model-generated mutation proposals against the guardrail.
6. Mistral Nemo was not run because available RAM is insufficient for a reliable 12.2B-model inference run.
7. Real-OVS executor latency was not measured. Do not substitute simulated fake-runner timings.
8. The old fake-runner latency figures are explicitly SIMULATED. They measure the software path with an in-memory command runner and stub connectivity callback, not live OVS or data-plane performance.
9. One regression test was skipped: tests/test_human_verifier.py::test_controller_records_openflow_port_down_event.
10. The 2026-10-27 standby-trunk PASS is historical and does not establish that the current testbed is healthy.
11. The project is not proven production-ready; the graph verifier is not a formal proof, the LLM evaluation is unusable for accuracy claims, and no new live Issue 2 anomaly was observed in this P2 run.
